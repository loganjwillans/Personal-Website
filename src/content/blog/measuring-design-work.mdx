---
title: Measuring design work without a dashboard
description: Most design metrics are proxies for someone else's job. A smaller set that has actually held up in reviews.

There is a version of design measurement that goes like this: instrument everything, build a
dashboard, watch the lines move up and to the right, and take credit for the quarter. I have never
seen it work, for a simple reason — the numbers that move on a two-week cadence are almost never
the numbers a designer influenced.

The numbers a designer does influence take longer and are harder to attribute. That does not make
measurement hopeless. It means the useful set is smaller than the one in the deck.

<Card title="Three kinds of evidence" label="What counts" color="green">

1. **Behaviour you can watch.** Time on task, completion, errors, support tickets per feature.
   Honest and comparable — and usually needs a baseline nobody collected.
2. **Judgement you can ask for.** Post-task confidence, "would you do this again?", "did you know
   what to do next?" Self-reported and soft, until six reviewers say the same thing.
3. **Decisions you can point at.** "We shipped inline annotation because five of six reviewers
   annotated manually in testing, and the sixth asked for the feature." That is reviewable in a way
   that a 3% lift is not.

</Card>

I stopped reporting numbers whose mechanism I could not explain. If I cannot say why the number
should move — through which behaviour, for which user, at which step — the correlation is
decoration. I also stopped treating any single number as the outcome. Time on task can improve
because the interface got faster or because people gave up sooner.

<LooseCard title="A worked example" color="cream">

On a contract review project we reported three things: median time to first decision before and
after, the number of panels in the default view, and post-task reviewer confidence on a five-point
scale. Each number had a mechanism, a comparison, and a limit.

<MetricGrid
  items={[
    { value: '41%', label: 'faster first decision', note: 'median, 24 sessions' },
    { value: '9 → 2', label: 'panels in the default view', note: 'we controlled this directly' },
    { value: '3.1 → 4.4', label: 'reviewer confidence', note: 'post-task, five-point scale' }
  ]}
/>

The first was the headline. The second was the one we could actually take credit for. The third
explained why the first was not just people clicking faster.

</LooseCard>

<Quote attribution="A sceptical VP of Product">

None of these numbers required a dashboard. Each one had a mechanism, a comparison, and a limit.

</Quote>

<Callout label="Honest summary" title="The discipline is not overclaiming" tone="blue">

Pick a small set of numbers. Know what they can and cannot tell you. Pair them with what people
said, and be explicit about the mechanism. The dashboard is optional; the mechanism is not.

</Callout>
